WHAT IT IS
----------
A Chrome extension that opens in a side panel on LeetCode. With a problem and
your (possibly buggy) solution, it gives you:
  * the SMALLEST input that breaks your code, plus your output, the expected
    output, and a plain-language root cause (Verify);
  * Socratic hints that guide you to the fix WITHOUT ever giving the full
    solution (Hints);
  * random test cases with expected outputs you can run locally (Test Cases).

The model never asserts a bug. It writes a guaranteed-correct brute force and a
random test generator; the backend RUNS both on ~60 seeded random inputs and
only reports a real mismatch (real input -> your output vs expected). That is
the "AI proposes, code verifies" pattern: no hallucinated explanations.

HOW IT USES THE MODEL API
-------------------------
- OpenAI-compatible Chat Completions endpoint (Adaption now; swappable to
  BharatCode qwen-3.8-27b). Model: Qwen 3.8 27B.
- op=generate (strict JSON schema) -> { entryName, bruteForceCode,
  generatorCode, userJs, maxInputSize, testCount }. userJs is a faithful JS
  version of YOUR code with the SAME bug (transcribed from C++/Python/etc.).
- op=run   -> node:vm executes the reference + your code on seeded inputs,
  finds the smallest failing input (bounded shrink search), per-run timeout.
- op=explain -> root cause from the REAL failing input + both outputs.
- op=hint   -> Socratic hint, never a full solution.
- Refuses false positives: if the reference and your code both throw on the
  same input, it reports an inconclusive "reference check".
- Resilient client: retries 503/429/5xx with backoff + jitter, honours
  Retry-After, 180s timeout, drops optional params on a 400, empty/truncated
  output = error.

SECURITY & GUARDRAIL
--------------------
- The model can ONLY do the 4 fixed ops with fixed prompts; the problem and
  code are wrapped as UNTRUSTED user data (prompt-injection safe).
- The API key lives ONLY on the backend (Render env var); the extension sends
  just a shared token + the task. A request without the token is rejected (403).
- Verification runs on a Node service (browsers and the free Cloudflare tier
  cannot run dynamically generated code), with a node:vm timeout so model code
  cannot hang the service.

RUN IT LOCALLY
--------------
1. cp .env.example .env   # set BHARATCODE_API_KEY (Adaption) + CXF_TOKEN
2. npm run install:all
3. npm run build && npm start     # backend on http://localhost:4000
4. Load the extension/ folder (unpacked) in chrome://extensions, point its
   Settings at the backend URL + token, open a LeetCode problem, click the icon.
